<section class="theory" markdown="1">

## Теоретические сведения
{: .section__title}

Сдача этого занятия состоит из трех частей. Файлы кейджа проверяет страница самопроверки: принтер, материал, масштаб, подпись, нарезанную деталь и высоту печати она читает прямо из файлов. Записи в `README.md` и напечатанные детали проверяет преподаватель. Файлы позвонка не сдаются: в них модель позвонка, которую нельзя выкладывать в открытый доступ, поэтому за позвонок сдаются напечатанная деталь и числа в `README.md`.

</section>

<section class="goal" markdown="1">

## 🎯 Цель работы
{: .section__title}

- проверить файлы кейджа на странице самопроверки;
- проверить, что в `README.md` заполнены все таблицы и выборы обоснованы;
- убедиться, что файлы позвонка не попали в репозиторий;
- сдать папку `print_5`.

</section>

<section class="subsection" id="s1" markdown="1">

## <span class="subsection__num">1.</span> Самопроверка файлов кейджа
{: .subsection__title}

1. Откройте страницу [проверки файлов Bambu Studio](../bambu-check.html).
1. Откройте в ней `cage_5.3mf`, затем `cage_5.gcode.3mf`. Файлы читаются только в вашем браузере и никуда не отправляются.
1. Все строки, по которым ставится зачет, должны быть зелеными. В проекте это принтер Bambu Lab A1 mini, материал Bambu PLA Matte, модель кейджа, масштаб 2 : 1 по всем трем осям и подпись, вырезанная в кейдже. В нарезанном файле — принтер, материал, G-код, объект с именем кейджа и высота печати кейджа 2 : 1 в одном из трех положений: около 15,8, 18 или 44 мм. Время, масса и поддержки показываются рядом с эталоном без оценки.
1. Откройте оба файла подряд, не закрывая страницу: она сравнит высоту кейджа в проекте с высотой печати в нарезанном файле. Красная строка «нарезанный файл не от этого проекта» означает, что после нарезки проект менялся: нарежьте его и сохраните оба файла заново.
1. Если строка красная, исправьте проект по подсказке страницы, нарежьте его заново и сохраните оба файла снова.
{: .steps}

</section>

<section class="subsection" id="s2" markdown="1">

## <span class="subsection__num">2.</span> Записи в README
{: .subsection__title}

Проверьте `README.md` по списку; эти записи проверяет преподаватель.

- Указан ваш позвонок; он не повторяет позвонок другого студента группы.
- Таблица положений позвонка заполнена для обоих положений, выбор записан одной фразой.
- Записаны общее время и масса нарезки позвонка, отправленной на печать.
- В таблице «предскажи и проверь» есть исходная нарезка копии, прогноз и факт для трех изменений и объяснение каждого расхождения.
- Таблица положений кейджа заполнена для трех положений, включая направление слоев относительно оси позвоночника; для выбранного положения заполнены оба типа поддержек.
- Выбор положения и типа поддержки кейджа обоснован по массе поддержек, времени и направлению слоев.
{: .checklist}

</section>

<section class="subsection" id="s3" markdown="1">

## <span class="subsection__num">3.</span> Файлы позвонка вне репозитория
{: .subsection__title}

1. Откройте терминал в папке `print_5` и выполните `git status`. Файлов позвонка в списке нет: их закрывает `.gitignore`. Если `vertebra_5.3mf` или файл позвонка (`L4.stl` и т. п.) есть в списке, в папке нет `.gitignore` из архива или файл позвонка переименован ([task 5-1](task_5-1.html), раздел 2): исправьте это до команды `git add`.
1. Выполните `git ls-files`: команда печатает файлы папки, которые git уже отслеживает. В списке не должно быть ни файлов `vertebra_5*`, ни файла позвонка.
1. Если файл позвонка есть в списке `git ls-files`, он попал в коммит раньше, чем в папке появился `.gitignore`: шаблоны на такой файл не действуют. Уберите его из репозитория, не удаляя с диска: `git rm --cached L4.stl` (с именем своего файла), затем сделайте коммит и повторите `git ls-files`.
1. Если коммит с файлом позвонка уже отправлен на сервер командой `git push`, файл остается в истории репозитория и после `git rm --cached`. Сразу сообщите об этом преподавателю и не открывайте репозиторий для других, пока история не очищена.
{: .steps}

<div class="check" markdown="1">

Проверьте себя
{: .check__title}

Папка готова к сдаче, если выполнены все условия. Проверка ничего не меняет в файлах.

| Показатель | Должно быть | Если не совпало |
|---|---|---|
| Самопроверка `cage_5.3mf` и `cage_5.gcode.3mf` | все строки зачета зеленые | исправьте проект по подсказке страницы проверки (раздел 1) |
| `README.md` | все таблицы и выборы заполнены | допишите по списку раздела 2 |
| `task_5-5_test.txt` | текст мини-теста [task 5-5](task_5-5.html) с вашей фамилией | пройдите мини-тест и скопируйте текст в файл |
| `git status` и `git ls-files` | нет `vertebra_5*` и файла позвонка | раздел 3 |

</div>

<section class="then" markdown="1">

## Затем
{: .then__title}

1. Добавьте в репозиторий файлы папки `print_5` из дерева ниже и сдайте папку так же, как папки предыдущих занятий.
1. Файлы позвонка оставьте у себя: они в репозиторий не входят.
1. Когда детали напечатаны, выполните [task 5-9](task_5-9.html) и отдайте позвонок и кейдж преподавателю.
{: .steps}

Файлы для сдачи:

```text
print_5/
├── .gitignore
├── cage_5.3mf
├── cage_5.gcode.3mf
├── README.md
└── task_5-5_test.txt
```
{: .folder-tree}

Если вы нарезали подставку, в папке лежат еще оба ее файла ([task 5-2](task_5-2.html), раздел 5); они не оцениваются.
