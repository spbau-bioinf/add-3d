# Практические занятия · Цифровой конвейер 3D-производства

Сайт собирается GitHub Pages (Jekyll) из Markdown-файлов этой папки.
Правите `.md` → Commit → Push → через 1–2 минуты сайт обновлен.

## Начало страницы

```yaml
---
work: 1                # номер занятия (из _data/nav.yml)
code: "task 1-3"       # код страницы
title: "Первый слой вручную: контуры и шов"   # заголовок в шапке
---
```

Необязательные поля: `kicker` (строка над заголовком, по умолчанию
«Практическое занятие #1 · task 1-3»), `head_title` (заголовок вкладки браузера;
нужен, если в `title` есть HTML-теги), `show_author: false` (скрыть подпись автора).

## Шпаргалка по разметке

**Обычный текст** — как в любом Markdown: `**жирный**`, `*курсив*`,
`` `код` ``, списки `-` и `1.`, таблицы `| a | b |`.
Ссылка на страницу того же занятия — `[task 1-4](task_1-4.html)`,
другого занятия — `[task 2-1](../task_2/task_2-1.html)`.
Спецсимволы `_ * [ ] |` в обычном тексте пишутся с `\`: `task\_1-3\_1.py`
(внутри `` `кода` `` — без `\`).

**Класс для абзаца, заголовка, списка** — строкой сразу под ним:

```markdown
Разбор
{: .analysis__title}
```

**Блоки-обертки** (теория, пример, задание, выноска…) — HTML-тег с `markdown="1"`.
Пустые строки после открывающего и перед закрывающим тегом обязательны,
текст внутри **без отступов**:

```markdown
<article class="task" id="task-1" markdown="1">

### Задание 1. Счетчик прочтений <span class="level level--1">Уровень 1</span>
{: .task__title}

Файл: <span class="task__file">task_1-3_1.gcode</span>
{: .task__meta}

Текст задания.

</article>
```

Классы оберток: `theory`, `goal`, `callout callout--hint|--warning|--important`,
`subsection`, `example`, `analysis`, `definition`, `task`, `task task--star`,
`final-task`, `capstone`, `overview`, `mistake`, `compare`, `then`.

**Код** — подпись «Код» ставится сама:

````markdown
```python
print(type(17))
```
````

Неверный / верный вариант и своя подпись:

````markdown
```python
print(gc_percent)
```
{: .code-block--bad}

```python
print('ok')
```
{: .code-block--good data-label="Полезный комментарий"}
````

**Вывод терминала** — подпись «Вывод терминала» ставится сама;
текст между `@@` выделяется как ввод пользователя:

````markdown
```text
What is your name?
@@Anna@@
Hello, Anna
```
{: .output}
````

Варианты: `{: .output .output--error}` (ошибка),
`{: .output .output--file}` (содержимое файла),
`{: .output data-label="Требуемый вывод"}` (своя подпись).

**Дерево папок** — `@@…@@` выделяет новую папку:

````markdown
```text
ivanov_ii/
└── projects_1/
    └── @@task_1_3/@@
```
{: .folder-tree}
````

**Просмотрщик G-кода и калькулятор** вставляются одной строкой, отдельным абзацем:

```markdown
{% include gcode-viewer.html presets="two,broken" default="two" %}

{% include e-calc.html %}
```

`presets` — кнопки готовых файлов: `two` (два слоя квадрата), `broken` (файл с ошибками),
`square` (квадрат из генератора), `scaffold` (скаффолд). `default` — файл, который
открывается, пока на странице ничего не сохранено. На одной странице — не больше
одного просмотрщика. Готовые файлы описаны в конце `assets/js/gcode-core.js`.
Внутри вставок и в тексте страниц нельзя использовать `@@` вне блоков вывода:
шаблон превращает текст между `@@` в выделение.

**Формула с расшифровкой** — по центру, под ней список «где»:

```html
<div class="formula"><i>P</i> ≈ 1 − <i>W</i> / <i>s</i></div>
<dl class="where">
<div><dt>где <i>P</i></dt><dd>пористость, доля</dd></div>
<div><dt><i>W</i></dt><dd>ширина дорожки, мм (<a href="task_1-2.html">task 1-2</a>, раздел 1)</dd></div>
</dl>
```

**Проверьте себя** — блок с таблицей «Показатель / Значение / Если не совпало»:

```markdown
<div class="check" markdown="1">

Проверьте себя
{: .check__title}

Зачем сверять эти числа.

| Показатель | Значение | Если не совпало |
|---|---|---|
| Слоев | 2 | ... |

</div>
```

**Мини-тест** — разметка в `assets/js/quiz.js` (шапка файла); `data-comment` задает знак комментария: `#` для Python, `;` для G-кода.

**Окно запуска Python** — код и требуемый вывод передаются через `capture`:

```liquid
{% capture code %}
import math
...
{% endcapture %}{% capture expected %}
E на 1 мм: 0.03326
{% endcapture %}{% include pyrun.html file="task_1-2_1.py" code=code expected=expected %}
```

Для программ с `input()` добавьте `stdin="0.7\n10\n20"`.

**Файл для скачивания** — положите его в `assets/files/` и дайте ссылку списком:

```markdown
- [broken.gcode](../assets/files/broken.gcode){: .files__link}
{: .files}
```

**Иллюстрация из источника** — картинку положите в `assets/img/`:

```markdown
<figure class="figure-src">
<img src="../assets/img/antar2026_fig15.jpg" alt="Описание">
<figcaption class="figure-src__caption">Подпись.<br>Источник: Автор et al., год, Fig. N, p. NN.</figcaption>
</figure>
```

**Схемы, блоки синтаксиса, сложные таблицы** остаются обычным HTML прямо
в `.md`-файле (`<figure class="diagram">…`, `<div class="syntax">…</div>`) —
Jekyll выводит его как есть.

## Как добавить страницу

1. Создайте `task_1/task_1-10.md` с «шапкой» из полей выше.
2. Добавьте ее в `_data/nav.yml` в нужное место списка `pages`
   (`url: task_1/task_1-10.html`). Меню, оглавление и кнопки перехода
   обновятся сами.

## Главная страница и меню

Тексты главной (название, описание, кнопки-ссылки, картинка в кружке)
меняются в `_config.yml`, раздел `home`. Картинку положите, например,
в `assets/img/avatar.png` и укажите `avatar: "assets/img/avatar.png"`.

Карточки занятий и боковое меню строятся из `_data/nav.yml`. Группа «Инструменты»
в боковом меню строится из списка `tools` в `_config.yml`. Адрес репозитория для
кнопки «GitHub» задается там же, в разделе `home`. Будущее
занятие можно показать заранее — на главной появится серая карточка
«Скоро», в меню его не будет:

```yaml
- work: 2
  title: "Практическое занятие #2"
  description: "Слайсинг: от STL к слоям."
  tags: ["Слайсер"]
  soon: true
```

Когда занятие готово, уберите `soon: true` и добавьте список `pages`
(или запустите конвертер — он допишет его сам, сохранив описание и метки).
У карточки может быть своя картинка: `image: "assets/img/task_2.jpg"`.

## Как перенести следующее занятие из HTML

HTML-файлы держите **вне** этой папки (иначе `task_2.html` и `task_2.md`
будут спорить за один адрес). Затем в корне сайта:

```
pip install beautifulsoup4 lxml
python tools/html2md.py путь/к/папке_с_html
```

Скрипт создаст папку `task_2/` со страницами и добавит занятие в `_data/nav.yml`.
Он печатает, какие блоки оставил в HTML (обычно сложные таблицы) — это нормально.

## Адрес сайта

Все ссылки на сайте относительные, поэтому при переносе на другой адрес
(например, `https://ИМЯ.github.io/` или свой домен) файлы менять не нужно.

## Просмотр на своем компьютере (необязательно)

Нужен Ruby (на Windows — RubyInstaller с DevKit). Один раз:

```
gem install bundler
bundle install
```

Затем при каждой работе:

```
bundle exec jekyll serve
```

Сайт откроется по адресу http://localhost:4000 и будет обновляться
при сохранении файлов (кроме `_config.yml` — после него перезапустите команду).
