## На этом занятии вы:
{: .section__title}

- Увидите, где G-код находится в цифровом конвейере: что происходит с моделью между STL-файлом и принтером и какие решения слайсер записывает в строки G-кода.
- Научитесь читать файл G-кода: отличать подготовку машины от слоев, рабочие ходы от холостых, абсолютный режим подачи нити от относительного.
- Рассчитаете подачу нити `E` из баланса объема и поймете, от каких параметров она зависит.
- Напишете первый слой вручную, а затем — генератор слоев на Python с контуром, заполнением и смещением шва.
- Сгенерируете решетку-скаффолд 0°/90° и свяжете шаг дорожек с ее пористостью.
- Разберете G-код слайсера как набор данных: число слоев, длина нити, масса, путь печати.

<section class="section" markdown="1">

## Зачем нужен этот материал
{: .visually-hidden}

G-код — последнее цифровое звено перед физической деталью. Все, что решено раньше, — модель, ориентация, поддержки, высота слоя — доходит до принтера только в виде строк G-кода. Кто умеет их читать, тот может проверить работу слайсера, найти ошибку до печати и спроектировать траекторию напрямую, когда траектория и есть проект изделия: например, у пористых скаффолдов для тканевой инженерии.
{: .lead}

## Как работать с материалом
{: .section__title}

- Проходите страницы строго по порядку: каждая следующая опирается на предыдущие. Страница [task 1-0](task_1-0.html) — теоретическая: заданий для сдачи в ней нет. Задания начинаются с [task 1-1](task_1-1.html); там же описано, как подготовить личную папку для работ.
- Каждый файл G-кода проверяйте в просмотрщике: он встроен в страницы с заданиями и доступен отдельно в разделе [«Просмотрщик G-кода»](../viewer.html). Сплошные линии — печать, пунктир — холостые перемещения, ползунок «Прогресс» проигрывает слой в порядке печати. Просмотрщик запоминает текст поля в браузере; на компьютере аудитории перед уходом нажмите «Очистить» на каждой странице, где вы им пользовались.
- Файлы G-кода — обычный текст. Создавайте их в редакторе кода и сохраняйте с расширением `.gcode`. Подойдет любой редактор: [VS Code](https://code.visualstudio.com/) — бесплатный редактор кода от Microsoft с расширением для Python, или [PyCharm](https://www.jetbrains.com/pycharm/) — среда разработки для Python от JetBrains, бесплатная в редакции Community.
- Программы на Python сохраняйте в отдельные файлы с именами из условия, например `task_1-4_1.py`. В конце каждой страницы с заданиями есть блок «Затем»: он говорит, в какую папку переместить файлы.
- Когда задание просит ответить словами, ответ записывается в тот же файл как комментарий. В G-коде комментарий начинается со знака `;`: все, что стоит правее него в строке, принтер пропускает. В Python комментарий начинается со знака `#`: все, что правее, интерпретатор пропускает. Пример ниже.
- Там, где вместо комментария стоит мини-тест, ответьте на его вопросы: после верных ответов он выдаст готовый комментарий, который нужно скопировать в конец файла.
- Любую программу преподаватель проверяет так: запускает ее на других входных данных и просит объяснить одну из ее строк или изменить программу. Программа, работу которой вы не можете объяснить, не засчитывается.
{: .checklist}

<aside class="callout callout--hint" markdown="1">

Где еще можно посмотреть G-код
{: .callout__title}

Основное место работы — [встроенный просмотрщик](../viewer.html). Для сравнения можно воспользоваться внешними сервисами:

- [NC Viewer](https://ncviewer.com/) — онлайн-просмотрщик и симулятор G-кода для станков с ЧПУ и 3D-принтеров;
- [gCodeViewer](https://gcode.ws/) — послойный анализ файла: время печати, расход пластика, высота слоя; работает локально в браузере;
- [PrusaSlicer G-code Viewer](https://help.prusa3d.com/article/prusaslicer-g-code-viewer_193152) — отдельная программа, открывает G-код разных слайсеров и проигрывает печать во времени;
- [Kiri:Moto](https://grid.space/kiri/) — бесплатный слайсер, работающий в браузере. Для итогового задания [task 1-6](task_1-6.html) он не подходит: там нужны профили PrusaSlicer, а без PrusaSlicer используются готовые файлы со страницы.

Внешние сервисы могут по-разному понимать отдельные команды; при расхождении ориентируйтесь на условия заданий.

</aside>
